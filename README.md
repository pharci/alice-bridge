# Alice Agent Bridge

Штатное распознавание Алисы → HTTP → любой агент → HTTP → штатный голос колонки.
Ядро не зависит от модели. Ollama — отдельный необязательный модуль.

Проверено на **Станции Мини 2 с root и сетевым ADB**. Для других моделей и прошивок
совместимость не проверена. Распознавание и голос требуют связи с сервисами Яндекса.

## 1. Подготовка с нуля

1. Установите [Python 3.10+](https://www.python.org/downloads/) с добавлением в PATH.
2. Скачайте [Android Platform Tools](https://developer.android.com/tools/releases/platform-tools),
   распакуйте и добавьте папку с `adb` в PATH. Либо укажите полный путь в конфиге.
3. Получите root и включите сетевой ADB на колонке: [подготовка колонки](docs/station-setup.md).
   Для уже настроенной колонки сброс и повторное получение root не нужны.
4. Компьютер и колонка должны быть в одной сети без изоляции клиентов. Найдите IP
   колонки в роутере и закрепите его DHCP-резервацией.
5. Скачайте этот репозиторий и откройте терминал в его папке. Зависимости pip не нужны.

Все адреса в публичных примерах условные. `192.0.2.10` замените IP своей колонки.

```powershell
python --version
adb version
adb connect 192.0.2.10:5555
adb devices
adb -s 192.0.2.10:5555 shell id
```

Нужны статус `device` и `uid=0(root)`.

## 2. Личный конфиг

```powershell
New-Item -ItemType Directory -Force .local
Copy-Item config/config.example.json .local/config.json
```

В `.local/config.json` задайте:

| Поле | Значение |
|---|---|
| `bridge.adb` | `adb` из PATH либо полный путь к исполняемому файлу |
| `bridge.serial` | `IP_КОЛОНКИ:5555` |
| `bridge.mode` | `auto`, `prefix` или `all` |
| `bridge.prefixes` | Обращения для явного выбора агента |
| `module` | `external` для своего агента; `ollama` для готового модуля |

В Windows пути в JSON пишутся как `C:/tools/adb/adb.exe` или `C:\\tools\\adb\\adb.exe`.
Личные настройки, архивы диагностики и логи исключены из Git.

## 3. Запуск

**Только мост, без встроенного агента:**

```powershell
python -m alice_bridge run
```

API слушает `http://127.0.0.1:19876`. После этого запустите своего агента.
Минимальный рабочий пример: во втором терминале `python -m examples.agent`.
Он отвечает фиксированной фразой; замените функцию `answer()` своим кодом.

**Мост вместе с Ollama:**

1. Установите и запустите [Ollama](https://docs.ollama.com/quickstart).
2. Загрузите нужную модель: `ollama pull MODEL_NAME`. Точное имя проверьте через `ollama list`.
3. В личном конфиге задайте `module: "ollama"`, `ollama.model` и при необходимости `ollama.url`.
4. Запустите:

```powershell
python -m alice_bridge up
```

`scripts/start.cmd` делает то же самое. Модуль прогревает модель и держит её в памяти
(`keep_alive: -1`). Для выгрузки по таймеру задайте, например, `"10m"`.
После остановки выгрузить вручную: `ollama stop MODEL_NAME`.

**Замена Ollama своим агентом:** остановите текущий запуск, задайте `module: "external"`,
снова запустите `up` и подключите своего потребителя HTTP API.
Либо запускайте процессы отдельно: `python -m alice_bridge run` и
`python -m modules.ollama` во втором терминале.

## 4. Подключение любого агента

1. Агент вызывает `GET /v1/requests?timeout=25`.
2. Мост возвращает `{"request_id":"...","text":"распознанный вопрос",...}`.
3. Агент обрабатывает текст любым способом и отправляет:

```http
POST /v1/responses
Content-Type: application/json

{"request_id":"...","text":"Ответ для озвучки"}
```

Самостоятельная озвучка без вопроса: `POST /v1/speak` с `{"text":"Сообщение"}`.
Этот вызов сразу включает голос. При обычном запуске мост ничего не произносит.

Для любого внешнего API достаточно заменить `answer()` в [примере агента](examples/agent.py).
Ключи провайдера и историю диалога хранит агент. **Один активный потребитель на мост**:
несколько потребителей делят очередь, а не получают копии вопросов.

Полный контракт, ошибки, тайм-ауты и удалённое подключение: [HTTP API](docs/api.md).

## 5. Голосовые режимы

| Режим | Поведение |
|---|---|
| `auto` | Действия умного дома, сценарии и прочие штатные действия остаются Алисе; речевые ответы идут агенту |
| `prefix` | Агенту идут только фразы с обращением из `bridge.prefixes` |
| `all` | Агенту идут все вопросы; короткие команды остановки и громкости остаются Алисе |

Пример явного обращения: «Алиса, агент, объясни, почему небо голубое».
В `auto` имена устройств и сценариев не прописываются: решение принимается по
директивам штатного ответа. Сценарий только с речью без признака действия может
попасть агенту; иногда до отмены успевает прозвучать начало ответа Алисы.

Ollama хранит четыре последние пары реплик в памяти процесса.
«Алиса, агент, новый диалог» очищает историю этого модуля.

## 6. Остановка и диагностика

```powershell
python -m alice_bridge status
python -m alice_bridge stop
python -m unittest discover -v
```

Также работают Ctrl+C и `scripts/stop.cmd`. Остановка `up` завершает и запущенный им модуль.
Обычная Алиса продолжает работать после остановки моста.

| Проблема | Проверка |
|---|---|
| ADB не подключается | IP, одна сеть, порт 5555; [повторное включение ADB](docs/station-setup.md#если-adb-пропал) |
| Ответ есть, звука нет | `audio_warning` в `status`; громкость и динамик в приложении/на колонке |
| Вопрос принят, ответа нет | Запущен ли агент; `module_ready`, `busy`, `last_error` в `status` |
| Ollama долго отвечает | Модель загружена, хватает памяти; параметры `keep_alive` и `num_ctx` |
| Порт занят | Уже работает другой экземпляр моста |

Логи ядра: `logs/bridge.log`. `last_answer` и `last_native_text` в статусе — текст,
а не доказательство слышимого воспроизведения. Громкость мост не меняет.
