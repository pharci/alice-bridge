# HTTP API v1

Базовый адрес: `http://127.0.0.1:19876`. JSON в UTF-8, тело запроса до 64 КиБ.
API использует один поток диалога и одного активного агента. Очередь в памяти;
перезапуск удаляет вопросы и историю доставки.

## Получить вопрос

```http
GET /v1/requests?timeout=25
```

`timeout` — целое число 0–25 секунд. Клиентский HTTP-тайм-аут должен быть больше.
Ответ `204` означает, что вопроса нет: повторите запрос.

Ответ `200`:

```json
{
  "request_id": "opaque-id",
  "text": "Сколько будет два плюс два?",
  "created_at": 1700000000.0,
  "timeout_s": 180
}
```

`request_id` нельзя подменять. Вопрос выдаётся одному потребителю один раз.
После падения потребителя автоматической повторной выдачи нет: пользователь может
повторить вопрос. `timeout_s` отсчитывается от постановки вопроса в очередь.

## Вернуть ответ

```http
POST /v1/responses
Content-Type: application/json

{"request_id":"opaque-id","text":"Четыре."}
```

Ответ `200`: `{"submitted":true,"duplicate":false}`.
Повтор той же пары ID/текст вернёт `duplicate:true` и не включит голос повторно.
Другой текст для уже отвеченного ID даёт `409`.

Новое голосовое обращение или остановка отменяет предыдущий ответ.
Поздний/просроченный ответ получает `409`, неизвестный ID — `404`.
`submitted` подтверждает отправку штатному движку, не воспроизведение динамиком.
Markdown, блоки кода, `<think>` и переносы строк очищаются; речь ограничена 900 символами.

## Остальные вызовы

| Метод и путь | Тело | Назначение |
|---|---|---|
| `GET /v1/health` | — | Состояние, папка запуска, последняя реплика, звук |
| `POST /v1/errors` | `{"request_id":"...","error":"provider_unavailable"}` | Завершить вопрос с ошибкой без звука |
| `POST /v1/module` | `{"name":"my-agent","ready":true}` | Показать готовность модуля в статусе |
| `POST /v1/speak` | `{"text":"Сообщение"}` | Сразу произнести текст независимо от вопроса |
| `POST /v1/ask` | `{"text":"Вопрос агенту"}` | Вставить вопрос с ПК в очередь; ответ `202` |
| `POST /v1/stop` | `{}` | Остановить ядро |

`/v1/ask` следует выбранному режиму. В `prefix` текст должен начинаться с обращения.
Старые пути `/health`, `/ask`, `/speak`, `/stop` оставлены как алиасы.
`module_ready` — последняя отметка агента; это не проверка живого процесса.

Ошибки: `400` — неверные поля/JSON; `401` — токен; `403` — запрос из браузера с Origin;
`413` — размер тела; `415` — Content-Type; `503` — транспорт колонки недоступен.

## Пример своего агента

```python
from modules.client import BridgeClient, APIError

client = BridgeClient("http://127.0.0.1:19876")
while True:
    request = client.poll()
    if request is None:
        continue
    answer = my_agent(request["text"])  # свой агент или вызов внешнего API
    try:
        client.respond(request["request_id"], answer)
    except APIError as error:
        if error.status != 409:
            raise
```

Python не обязателен: достаточно обычных HTTP-запросов из любого языка.
Рабочая заготовка: [examples/agent.py](../examples/agent.py).

## Агент на другом компьютере

По умолчанию API доступен только локально. Для сети:

1. В личном конфиге задайте `bridge.host: "0.0.0.0"`.
2. Перед запуском в терминале установите секрет:

```powershell
$env:ALICE_BRIDGE_TOKEN = "REPLACE_WITH_A_LONG_RANDOM_SECRET"
python -m alice_bridge run
```

3. На стороне агента используйте `http://IP_КОМПЬЮТЕРА_С_МОСТОМ:19876`
   и заголовок `Authorization: Bearer ...` во **всех** запросах.
4. Разрешите порт в межсетевом экране только для своего агента.

`BridgeClient(url, token)` добавляет заголовок сам.
`modules.ollama` принимает `--bridge-url URL`; секрет читает из переменной,
указанной в `bridge.token_env`. Ядро откажется слушать внешний интерфейс без секрета.
Для доступа через интернет используйте VPN или HTTPS-прокси: встроенный сервер — HTTP.
Ключи внешнего API остаются у агента и в мост не передаются.
